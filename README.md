# Letterbox Lock Singapore — Static Site (single source of truth)

Dependency-free static site. **One config file (`src/data.mjs`) drives everything** —
homepage, seven service pages, four legal pages, form options, `<meta>`, JSON-LD,
`robots.txt` and `sitemap.xml`. The runtime JS is progressive enhancement only.

## Quick start

```bash
npm run build        # node build.mjs && node build-pages.mjs
npm test             # 11 unit + integration tests (node --test)
npm run check        # quality gate (checks.mjs)
npm run standalone   # single-file preview.html (double-click friendly)
npm run preview      # serve at http://localhost:8080
```

## ⚠️ Testing the ORDER form locally (important)

The Order form's **colour dropdown updates by JavaScript** to match the selected
product. Modern browsers **block ES-module scripts when a page is opened directly
from disk** (the `file://` protocol) for security. So if you **double-click
`index.html`**, the script can't load and you'll see only the first colour
(Silver) — this is a browser rule, not a bug in the site.

Two correct ways to test locally:

1. **Open `preview.html`** (generated by `npm run standalone`) — it inlines the
   script, so it works from a double-click.
2. **Run a local server** — `npm run preview`, then open `http://localhost:8080`.

On your real hosting (served over http/https) `index.html` works perfectly — this
is verified by an automated integration test (see below).

This is enforced two ways so it can never silently drift:
- **`tests/message-privacy.test.mjs`** asserts the data matches the table.
- **`tests/colour-form.test.mjs`** is an *integration* test — it loads the built
  `index.html`, runs the real `app.mjs`, then selects P1…P9 and asserts the colour
  dropdown updates correctly each time. Belt-and-suspenders: each product `<option>`
  also carries a `data-colours` attribute as a fallback source.

## Before you go live — edit `src/data.mjs` only, then rebuild

| Field | Placeholder | Action |
|---|---|---|
| `baseUrl` | `https://www.example.sg` | your real domain |
| `phoneE164` / `phoneDisplay` / `whatsappNumber` | `6583417888` / `+65 8341 7888` | confirm real number |
| `reviewSourceUrl` | `https://g.page/example` | your real Google profile |
| `assets/img/**` | generated placeholders | real product + installation photos |

`checks.mjs` warns (not fails) on any remaining placeholder so CI stays green in
preview but reminds you before launch.

## Ranking on Google — code vs. off-page

The code maximises on-page SEO (crawlable static HTML, unique titles/descriptions,
JSON-LD LocalBusiness + Service + FAQ + Breadcrumb + Reviews, fast CSP-safe assets,
mobile-first, sitemap + robots). Ranking #1 also needs off-page work: verify a
**Google Business Profile**, collect **real Google reviews**, submit the sitemap in
**Search Console**, and get a few **SG directory listings**.
